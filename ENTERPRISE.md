# DimPack3D — Enterprise Value Architecture

_Written 2026-07-04. Companion to ROADMAP.md (phases/market) and BILLING-SETUP.md (payments plumbing). This document answers one question: **what makes this product genuinely worth a six-figure contract, and in what order do we build that worth?**_

## 0. The core thesis

Software pricing anchors to the size of the problem the product **owns**, not the size of the codebase.

- A tool that answers *"how should I load this container?"* is worth $29/month — and is easy to dismiss with "we'll just pay a little".
- A system that a logistics operation **runs on** — where plans, history, approvals and integrations live — is worth six figures, the way AutoCAD is worth its price because the industry's work product (drawings) lives inside it.

Everything below is the ladder from tool to system.

## 1. What six-figure buyers actually pay for

Verified context (research 2026-07-04): enterprise slotting/load software (Softeon Slot3D, Körber, SAP EWM) runs **$100K–$500K+/yr**; SMB WMS runs $500–1,800/mo but ships **no visual load/slotting capability**. The gap between them is real and underserved.

Buyers at that level are not buying features. They are buying:

| They pay for | Meaning | Product implication |
|---|---|---|
| **Operational continuity** | Their plans, history and data live in the product and they return daily | Workspaces, saved plans, shipment history (data gravity) |
| **Integration** | It talks to their ERP/WMS/order flow; removes daily manual work | CSV import → API → connectors (paid per-client) |
| **Org-level workflow** | Many users, roles, approvals, audit trail — the company adopts it, not one person | Multi-user, approval flow, audit log |
| **Risk transfer** | SLA, support, vendor accountability; someone answers at 2am when the container is at the dock | Support tiers, status page, named contacts |
| **Measurable ROI** | The internal champion needs one slide to justify the invoice | Auto-generated ROI dashboard (see §3) |

## 2. Their concerns (the procurement checklist we must pre-answer)

1. **"Will you exist in two years?"** — our biggest weakness as a new vendor. Antidotes: public changelog, status page, real case studies, and a standing promise of **full data export at any time, no ransom**. Procurement inspects the exit before entering; a generous exit lowers the barrier to entry. Retention comes from gravity and quality, not lock-in.
2. **Data security** — today's "computation never leaves your device" is a genuine differentiator; the moment server-side workspaces exist we must answer: where data lives, encryption, DPA, deletion SLA; SOC 2 once revenue justifies it.
3. **Cost of switching IN** — see §4.
4. **Support** — response-time tiers are part of the product, not an afterthought.
5. **Will warehouse staff actually use it?** — "if you can drag a box you can plan a container" is our counter to CAD-class training burden. Say it, demo it, and keep it true.

## 3. The build ladder (tool → system of record)

### Tier 1 — data gravity (the decisive jump)
- **Workspaces + saved plans + shipment history.** The moment plans live in the product, every additional plan raises the customer's cost of leaving. Foundation: existing Supabase auth scaffold (L5) + plans tables.
- **ROI dashboard — the six-figure slide, generated by the product itself:**
  > "This quarter: 87 containers planned · avg utilization 84% vs your 71% baseline · ≈ $46K freight saved."
  Inputs: per-plan utilization (we already compute), container costs (user-entered or defaults), a baseline (first N plans or user-declared). Honest math, shown with its assumptions.
- **Multi-user + roles + plan approval** (planner proposes → ops approves) and an **audit trail** (who moved which carton, when). These two features alone re-class the product from "calculator" to "system" in a buyer's eyes.

### Tier 2 — integration (the moat)
- **Excel/CSV import first** — 100% of prospects have carton lists in Excel. One-click import is the single largest switching-cost reducer we can build.
- **Documented public API** — the bin-packing engine is already a pure, dependency-free module; exposing it is natural. API keys per workspace; also the future "license the engine" exit path.
- **ERP/WMS connectors** — built per-client, charged per-client ($5–15K each). Integration work is services revenue, not a free feature.
- **SKU / carton library** — customer master data inside the product; more gravity.

### Tier 3 — trust artifacts
- Security page (architecture, data flow), public status page, SLA tiers, design-partner case study with verified numbers, public changelog.

## 4. Switching costs — both directions, deliberately

- **Lower the way IN**: Excel import; pilot packages include **white-glove onboarding — we digitize their carton/warehouse data for them** (this labor is part of what the $10–25K pilot buys).
- **Widen the way OUT**: full export, documented formats, no exit fees — stated publicly. This is a trust weapon, not a leak: gravity (history, workflow, integrations) is what retains, and it retains harder when the door is visibly open.
- **Replace the incumbent's job completely**: the real incumbent is usually **Excel + tribal knowledge**, not EasyCargo. The replacement is not a better calculator — it is the whole loop: *plan → approve → execute at the dock → measure → report*. Owning the loop is what justifies owning the budget line.

## 5. Pricing architecture (making six figures legible)

```
Free (today)              bottom-up wedge: planners inside target orgs adopt it themselves
Team  $99–299/mo          saved plans, multi-user, API-lite — small forwarders/importers
Enterprise (custom)       SSO, integrations, SLA, multi-site, onboarding services
                          license ($30–60K/yr) + implementation services = six-figure contracts
```

Six-figure deals are almost always **license + services**. The services line (onboarding, data digitization, connectors, layout consulting) is not overhead — it is how the contract reaches six figures while genuinely de-risking the customer.

## 6. The realistic path (no leaping)

1. **Build Tier 1** (workspaces, saved plans, ROI dashboard, approvals). Prereq: dedicated Supabase project (BILLING-SETUP.md §1).
2. **Sign 2–3 design partners** at $10–25K pilots using the warehouse/enterprise demo + Tier 1. Contractual success metric: utilization uplift ≥8% or search-time halved.
3. **Pilots generate the verified ROI case study** — the ammunition without which no six-figure conversation survives procurement.
4. **Then** enterprise motion: security page + SLA + connectors per signed customer, services attached.

The free site stays: it is the top-of-funnel, the credibility artifact ("try the engine yourself"), and the bottom-up adoption channel into target organizations.

## 7. Metrics that tell us it's working

- Plans saved per returning workspace (gravity) · weekly returning workspaces
- Share links opened by non-creators (organic spread into orgs)
- `waitlist_warehouse` count (which market pulls) · export conversion (willingness to identify)
- Pilot conversations opened / signed · pilot ROI numbers achieved vs promised
