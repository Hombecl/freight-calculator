# Planner handoff and customer-value release — 21 October 2026

Planner now re-screens current manual/shared positions for identity/counts, bounds, overlap, base support (same 60% model as the solver), equal-support stacking loads, orientations, weights, payload, possible door passage and conservative straight-door unload order. Invalid or incomplete plans remain exportable as visibly marked drafts. Successful workflow-output analytics requires a complete, screened result, not only equal carton counts. These checks do not certify securing, actual loading paths or transport safety.

Stable `specId` connects each placement with its original cargo row; unambiguous generated IDs support old snapshots. Reconciliation never matches display labels. Remaining cargo is listed per row in the UI, PDF and CSV. Only demonstrable dimension, door or single-carton payload failures are called causes; other remainder is explicitly an unsolved/current-layout result.

PDF views are customer summary, warehouse steps and forwarder positions. All include reconciliation, revision and review status. Warehouse reports include bounded numbered top views and the support-first sequence table; top views can occlude stacked cartons, so height remains in the table. Planner CSV is now a record-based manifest: `cargo`, `placement`, `issue`, `assumption` with job/revision/status. Other tools retain their existing placement CSV format. Integrations consuming Planner CSV must select `placement` records and the named headers; this is a deliberate schema change.

Comparison transfers preserve orientation and unload settings, explicitly retaining the planner default of unrestricted tilt where applicable. Cargo groups become PO groups; the visible consolidation rules still control PO splitting and may be adjusted by the user. Comparison creates candidates in the existing consolidation tool; it does not overwrite the original manual layout. Costs require the user's quotes.

Local history keeps the latest 20 immutable content versions in the same browser. Comparison saves the current version before navigation. Reopening preserves the job but resets own-job confirmation. Starting another job preserves cargo inputs/rules and recalculates the layout, clears the report reference and creates a different job identity. Local versions are not a cloud backup. Existing cloud workspace is unchanged. Shared snapshots carry job reference and overhang so recipients screen the same envelope.

`export_usefulness` records one-click usable/edit/explore separately from optional `export_feedback` detail submissions. Optional `export_recipient` and `export_choice` use fixed enums only. Do not sum these events as respondents or outputs. Session suppression starts on the first answer, even if extra details are abandoned. Shipment data, email, job IDs and hashes are not sent through these events. Feedback is self-selected and exports still do not prove saving or actual shipment use.

Validation includes unit fixtures for missing support, support movement, stacking load propagation, bounds/overlap, original orientation, door/payload, repeated labels, unknown identities, report escaping, draft PDF/CSV, immutable revisions and no-rotation comparison. Browser CI checks shared draft PDF/reconciliation, cargo transfer/history and one-click feedback. Live QA uses local sample inputs only; no customer outcomes are claimed.
