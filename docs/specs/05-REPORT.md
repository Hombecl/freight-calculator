# Spec 05 implementation report

Implemented `/box-catalog`, `/zh/box-catalog`, and `/api/box-catalog`. No commit, push, deployment, dependencies, secret changes, or prerender-script changes.

## Files and requirements

- `src/lib/boxCatalog.ts`: exported request/result types, `optimizeBoxCatalog(input: unknown)`, validation and cm/kg normalization, both-unit dimensions/weights, SHA-256 input identity, and version `box-catalog-v1`. SKU/order/quantity/catalog/search limits are validated with `PalletInputError` field paths. Duplicate SKU and box IDs are rejected; duplicate order lines are aggregated before quantity limits are checked.
- Fit screening calls `packContainer` with all requested units. Upright preserves the vertical dimension; fragile maps to `maxStack: 0`. Fits are cached by order lines and box definition. Unfit orders remain in `perOrder`, retain lines/counts, have `boxId: null`, and contribute to weighted totals and `ALL_ORDERS_FIT: fail`.
- Absent candidate pools are generated by bounded cube growth, cropped to packed bounding dimensions, rounded upward to 1 cm or 0.5 in, deduplicated, and capped at 40. Supplied pools are limited to 40. Boxes allow dimensions large enough to reuse generated multi-unit envelopes in `chooseBox`.
- Search starts with maximum item-volume-weighted history coverage, adds boxes by objective improvement, and attempts single swaps within the objective-evaluation budget. It returns exactly `catalogSize` boxes when the pool is large enough. The response identifies candidates, evaluated combinations, and budget.
- Billing uses `max(actual, dimensional, minimum billable)`, correctly converting input units independently of divisor/rate units. Rates, void-fill cost, optional box cost, and history counts feed the monetary estimate. Baseline uses current boxes with the same evaluation. Savings include billed-weight percentage and monetary savings per 1,000 orders when a rate is available.
- Every optimizer/picker result includes the four requested checks, `CHECK_SEMANTICS`, hash, engine version, and both requested limitation notes. Missing rates return `RATE_PROVIDED: not_evaluated` and omit monetary estimates.
- `chooseBox(order, catalog)` accepts SKU definitions, billing, optional request units, and single-order `lines`; catalog dimensions/weights use request units. It chooses the complete fit with smallest billed weight and returns the actual packing result, selected box, and the common result metadata. Failed fits return all requested units as unplaced.
- `src/lib/boxCatalogImport.ts`: pure CSV/TSV order-history grouping. Repeated lines aggregate within an order; equivalent shapes combine with counts. Invalid rows fail rather than disappearing. The first order ID labels a compressed shape.
- `functions/api/box-catalog.ts`: streamed 96 KB body limit, JSON content-type checking, 200/400/413/415 responses, field errors, CORS, keyed rate limiting (anonymous 5/min and 50/day), tier, invalid-key warnings, OPTIONS, and GET discovery/example documentation.
- `src/pages/BoxCatalogPage.tsx`: bilingual three-step SKU paste/upload (`importCartons`), history paste, optional current/candidate box JSON fields, catalog size, input/billing units, divisor presets/custom divisor, minimum/rate/void-fill controls. Results include catalog shares, baseline comparison, savings, filterable per-order billing, highlighted unfit rows, checks, and search count. Downloads include catalog CSV, order CSV, and submitted request JSON, with curl. The single-order form uses `chooseBox`.
- `src/components/InteractiveLoadPlanner.tsx`: additive read-only mode disables box editing and keyboard mutations while retaining camera navigation. `placedCountTestId` exposes the same placement-array length used by the renderer. The page sets `box-placed-count`.
- `src/lib/dimPresets.ts` and `src/pages/DimWeightCalcPage.tsx`: extracted the existing FBA 139, UPS/FedEx 139, express 5000, and air 6000 constants for shared use. They are explicitly marked `template: true`; the catalog page asks users to verify them with their buyer/carrier.
- Route/discovery registration: `src/App.tsx`, `scripts/release-routes.mjs`, `src/components/layout/Footer.tsx`, `public/llms.txt`, and `src/pages/ApiDocsPage.tsx`. API limits/label: `src/lib/apiTiers.ts`, `src/pages/ApiPricingPage.tsx`. Page metadata and `tool_box_catalog` / `box_catalog_run` tracking are present.
- Tests: `tests/box-catalog.mjs`, `package.json`, and the new browser scenario in `tests/e2e.mjs` immediately before the Chinese-homepage test.

## Modelling decisions and known limits

- This is a deterministic heuristic, not an optimum or proof of infeasibility. Cube generation grows by 15% per attempt; it does not solve a minimum-volume packing problem. If more than 40 unique generated bounds exist, the largest by volume are retained; uncovered orders remain explicitly unfit.
- `searchBudget` counts objective evaluations during catalog search. Fit preparation, final result aggregation, and baseline aggregation are separate. If a very small budget expires before forward selection is complete, remaining slots fill in stable pool order; this is documented in API help.
- The objective uses monetary cost when a rate is supplied, otherwise billed kg. Box and void-fill costs use the same caller-selected currency. No currency conversion is implied. Monetary savings are omitted without a rate, including when void-fill or box costs alone were provided.
- Unfit orders use the largest candidate by volume as a comparison charge, including baseline evaluation. This is flagged, never presented as a shippable order or tariff quote. Negative savings are retained.
- No cushioning/dunnage, carton tare, wall-thickness allowance, carrier rounding, tariff verification, or stability certification. Supplied dimensions serve both fit screening and DIM arithmetic. Fragile has the existing packer's zero-supported-weight semantics. These limitations and the availability of Paccurate/Packsize for enterprise workflows appear on the page.
- All specified implementation features are included. No new check emits `warn`; the requested missing-rate condition is `not_evaluated`.
